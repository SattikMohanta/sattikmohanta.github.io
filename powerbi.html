Star Schema vs. Flattened Data Ingestion Core Architecture

The VertiPaq engine utilizes columnar storage. Wide, denormalized single tables store duplicate text across millions of rows, increasing dictionary memory overhead.

✅ DOs

  • Transform tables into a pure Star Schema (1:Many relationships from Dimensions to Facts).
  • Split high-cardinality DateTime columns into separate Date and Time integer fields.
  • Set surrogate keys and foreign keys to Do Not Summarize.

❌ DON'Ts

  • Do not leave source auto-detected relationships as Many-to-Many without a bridge table.
  • Do not keep auto-generated Auto Date/Time hierarchies enabled in large models.
  • Do not import raw surrogate keys formatted as strings/text.
DAX Evaluation Context & Context Transition DAX Engine

A naked measure invoked inside an iterator automatically wraps an implicit CALCULATE, initiating context transition.

// Context Transition in Action
Total Customer Sales = 
SUMX(
    DimCustomer,
    [Total Sales] -- Implicitly CALCULATE([Total Sales])
)

✅ DOs

  • Use KEEPFILTERS() when you want CALCULATE to intersect instead of overwrite existing visual filters.
  • Use DIVIDE(Numerator, Denominator, Alternate) to prevent divide-by-zero errors.
  • Cache intermediate filter sets in DAX Variables (VAR) to avoid re-evaluating expressions.

❌ DON'Ts

  • Do not use FILTER(ALL(Table), ...) when a simple boolean predicate inside CALCULATE suffices.
  • Do not use IFERROR() for safe division (it forces single-threaded formula engine evaluation).
  • Do not assume variables recalculate inside iterators; DAX variables are immutable and evaluated at declaration.
Dynamic Row-Level Security (RLS) & Object-Level Security (OLS) Enterprise Governance

Dynamic RLS filters data based on authenticated User Principal Names (UPN). Object-Level Security restricts access to entire tables, columns, and measure metadata.

✅ DOs

  • Use USERPRINCIPALNAME() rather than USERNAME() in the Power BI Service.
  • Configure Object-Level Security using external tools like Tabular Editor by setting MetadataPermission = None.
  • Assign users to the Viewer workspace role if RLS enforcement is required.

❌ DON'Ts

  • Do not expect RLS to restrict workspace Admins, Members, or Contributors (they have edit rights and bypass RLS).
  • Do not build circular bidirectional paths to propagate RLS across bridge tables.
  • Do not create calculated columns containing USERPRINCIPALNAME() (evaluated at refresh, not per-user query).
Formula Engine (FE) vs. Storage Engine (SE) Performance Optimization Architect Level

DAX performance bottlenecks typically stem from single-threaded Formula Engine loops caused by row-by-row iteration or context-transition overhead inside large loops.

✅ DOs

  • Trace queries using DAX Studio to verify high Storage Engine (SE) CPU percentages and low FE millisecond times.
  • Configure User-Defined Aggregations for DirectQuery models to satisfy high-level queries directly from in-memory cache.
  • Partition high-volume tables with RangeStart and RangeEnd parameters for Incremental Refresh.

❌ DON'Ts

  • Do not wrap iterative statements around measures inside visual aggregations when a simple sum over a table suffices.
  • Do not cross storage boundaries (e.g., DirectQuery joining an Import dimension) without verifying limited relationship query plans.
  • Do not leave unused columns with cardinality exceeding 1,000,000 in your VertiPaq model.

1. Omnichannel Rolling 30-Day Window (Amazon / Flipkart Scenario)

Amazon Medium

Using FactSales (loaded from Case Study 1), what is the total sales value returned by a measure calculating the rolling 30 days of sales as of 2025-02-28?

Pattern Clue: Use CALCULATE, REMOVEFILTERS(DimDate), and set bounds between MAX(DimDate[Date]) - 29 and MAX(DimDate[Date]).
Verified Production Solution: 
Rolling_30D_Sales = 
VAR _MaxDate = MAX(DimDate[Date])
VAR _StartDate = _MaxDate - 29
RETURN
CALCULATE(
    SUM(FactSales[SalesAmount]),
    REMOVEFILTERS(DimDate),
    DimDate[Date] >= _StartDate && DimDate[Date] <= _MaxDate
)
// Resulting evaluated sum: 1844.96

2. High-Value Customer Churn Count (Deloitte / McKinsey GCC Scenario)

Deloitte Hard

How many unique customers made transactions in the 90 days prior to 2025-03-01, but have zero transactions recorded in the active March 2025 period?

Pattern Clue: Leverage EXCEPT(HistoricalCustomerTable, CurrentPeriodCustomerTable) and wrap in COUNTROWS().
Verified Production Solution: 
Lost_Customers_Count = 
VAR _CurrentPeriodStart = MIN(DimDate[Date])
VAR _HistStart = _CurrentPeriodStart - 90
VAR _HistEnd = _CurrentPeriodStart - 1

VAR _HistCust = 
    CALCULATETABLE(
        VALUES(FactSales[CustomerKey]),
        REMOVEFILTERS(DimDate),
        DimDate[Date] >= _HistStart && DimDate[Date] <= _HistEnd
    )
VAR _CurrCust = CALCULATETABLE(VALUES(FactSales[CustomerKey]))
RETURN
    COUNTROWS(EXCEPT(_HistCust, _CurrCust))
// Target Evaluated Count: 2
