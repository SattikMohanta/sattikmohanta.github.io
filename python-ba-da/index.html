# Class and Object
class Employee:
    company = "Acme"  # class attribute

    def __init__(self, name, salary):
        self.name = name          # instance attribute
        self.salary = salary

    def display(self):

📊 Window Functions in Action
See the table above for mapping; here are practical Python examples: 
# — ROW_NUMBER() per group —
df['row_num'] = df.groupby('dept').cumcount() + 1

# — RANK() per group —
df['rank'] = df.groupby('dept')['salary'].rank(method='min', ascending=False)

# — LAG / LEAD —
df['prev_month'] = df.groupby('product')['revenue'].shift(1)
df['next_month'] = df.groupby('product')['revenue'].shift(-1)

# — Running total per group —
df['running_total'] = df.groupby('region')['revenue'].cumsum()

# — % of group total —
df['group_total'] = df.groupby('region')['revenue'].transform('sum')
df['pct_of_group'] = df['revenue'] / df['group_total'] * 100

# — Rolling averages (moving windows) —
df['ma_3'] = df['revenue'].rolling(window=3, min_periods=1).mean()

Interview Edge — Real Experiences & Do's/Dont's

💡 Insights from Real Interviews
The following experiences come from actual BA/DA/BI interviews at Standard Chartered, Deloitte, PwC, and more. Use them to prepare effectively.

🏦 Standard Chartered — Data Analyst

  • Python data cleaning: How to handle missing values, duplicates, type conversions, and outliers — this is a must‑know.
  • Filling missing values: df['col'].fillna(df['col'].mean(), inplace=True) and df['col'].fillna(df['col'].median(), inplace=True)
  • Date conversion: df['date'] = pd.to_datetime(df['date'], format='%Y-%m-%d')
  • SQL scenario: Given a customer table (name, date, balance, country) — get the latest daily record per customer and compute monthly total balance. Use ROW_NUMBER() partitioned by customer to get latest.
  • Key takeaway: The interviewer cares about how you connect your analysis to business outcomes — not just code or dashboards, but the story behind the data.

🏢 Deloitte — Data Engineer

  • SQL: 3rd highest salary query, deduplication, WHERE vs HAVING, index principles.
  • Python: Handling large CSV files, map/filter/reduce differences, database connections, try‑except error handling.
  • PySpark & Big Data: RDD vs DataFrame, CSV reading, shuffle operations, performance tuning, Delta Lake schema evolution.
  • Production issues: How would you debug a pipeline that failed at 2 AM? How to monitor and alert?

📊 PwC — Data Analyst (CTC 18 LPA)

  • SQL: Cumulative revenue (window functions), Top 5 products, customers who bought in consecutive months, monthly retention, dynamic Nth highest salary, index optimisation, JOIN type differences.
  • Python: Find unique pairs in a list that sum to a target, palindrome check (ignore spaces/punctuation/case), deep copy vs shallow copy, decorators.
  • Estimation questions: Annual smartphone sales in India, daily revenue of a roadside tea stall.

📋 Do's & Don'ts

  • ✔ DO — Always ask clarifying questions before writing code. Understand the business context and edge cases. Interviewers value problem‑solving over speed.
  • ✘ DON'T — Jump straight into code. Many candidates start coding without clarifying the dataset, missing values, or expected output. This signals impatience.
  • ✔ DO — Use method chaining and clean variable names. It shows you care about code quality and maintainability. Senior interviewers notice this immediately.
  • ✘ DON'T — Ignore performance. Using loops instead of vectorised operations is a common red flag. Mention alternatives like apply() vs vectorisation.
  • ✔ DO — Mention data quality (nulls, duplicates, outliers) for every dataset you work with. This is a hallmark of a seasoned analyst.
  • ✘ DON'T — Forget to validate your output. Always suggest sanity checks (row counts, totals) to catch bugs early.
  • ✔ DO — Proactively discuss how you'd scale your solution to larger datasets (chunking, Dask, PySpark). This differentiates you from tutorial‑only candidates.

🧠 Situational & Behavioral Q&A

  • Q: "A stakeholder repeatedly asks for new metrics after the dashboard has been finalised. What do you do?"
    ✔ Approach: Acknowledge the request, assess the impact on delivery timeline, propose a phased approach (e.g., include in next sprint), and document changes. Maintain open communication about trade‑offs.
  • Q: "You discover that a key data source has a critical error that invalidates your analysis. The report is due today. How would you handle it?"
    ✔ Approach: Immediately inform stakeholders of the issue, explain the impact, and provide a revised timeline. If possible, use alternative data or partial analysis to mitigate. Document the issue for future prevention.
  • Q: "How do you ensure data quality in a pipeline that ingests data from multiple sources?"
    ✔ Approach: Implement data validation checks (e.g., schema validation, row count, null checks, outlier detection), use logging and monitoring, and set up alerts for anomalies. Also, maintain a data dictionary and unit tests for transformations.
  • Q: "How would you explain a complex model (e.g., Random Forest) to a non‑technical business executive?"
    ✔ Approach: Use analogies (e.g., "It's like a panel of experts voting"), focus on the business problem it solves, and highlight key drivers (feature importance) rather than mathematical details. Always link to business outcomes.
